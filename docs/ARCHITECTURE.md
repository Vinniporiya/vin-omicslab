# Vin-OmicsLab: architecture and roadmap

This is the pre-implementation document set the brief asked for, written after the first build. Each section says what is
**built** in this repository and what is only **specified** for a later phase. Nothing specified is presented as working.

Status key: **Built** (in `src/`, exercised by `scripts/selftest.ts` or the UI) · **Specified** (design only).

---

## A. Product architecture

Vin-OmicsLab grows in three layers that share one data model and one evidence rule.

| Layer | Purpose | Status |
|---|---|---|
| 1. Research portfolio | Explain the science: questions, projects, methods, publications, about | Built (content awaiting author input) |
| 2. Research platform | Interactive analyses on a dataset, each with method record and evidence; gene atlas with genome pages | Built: expression simulated, genome annotation live from Ensembl |
| 3. Product | Accounts, uploads, real compute, literature intelligence, teams | Specified (Phases 2 to 5) |

Cross-cutting rules, enforced in code rather than in prose:

- **Evidence hierarchy** (`lib/evidence.ts`): observed, statistically supported, literature supported, model inference, hypothesis. Levels are never merged. `validateClaim()` rejects, for example, a statistical layer without a test, adjusted P and run ID.
- **No fabrication.** Publications, affiliations, clients and results are empty until supplied. Placeholders are labelled (`ContentStatus`).
- **Reproducibility by design.** A run carries a provenance record; `assessReproducibility()` reports missing items instead of asserting success.
- **Simulation is always labelled.** The dataset is generated by a seeded simulator and carries `provenance: 'simulated'`; every panel shows a "Simulated data" badge.

## D. Design system

Direction: premium scientific, editorial, minimal, technical. Dark by default with a complete light theme.

- **Themes** (`app/theme.ts`, `styles/tokens.css`): System (follows OS live), Hematoxylin (dark, default), Eosin (light), Journal (warm paper, print-oriented), High contrast. Chosen in the header Display menu, stored in localStorage; `<meta name="theme-color">` follows the theme. Print styles hide chrome.
- **Data palette**, independent of theme: Histology (default) or Colour-vision safe (Okabe-Ito). Applied in `data/useDataset.ts` as a memoised recoloured view of the dataset, so every figure and export follows it. Nine cell types exceed Okabe-Ito's eight colours, so the ninth uses the theme's ink colour; legend isolation remains the reliable way to separate categories.
- **Palette** (`styles/tokens.css`): histology-derived. Hematoxylin blue-violet for surfaces, eosin rose as the single interface accent. Data colours belong to the data (cell types, conditions) and are not reused for chrome.
- **Type:** Newsreader (serif) for headings and ledes, IBM Plex Sans for text, IBM Plex Mono for code. Fonts load from Google Fonts and fall back to system serif/sans when offline.
- **Evidence encoding:** each level has a colour *and* a distinct mark shape (circle, square, diamond, triangle, dashed circle) so it is readable without colour.
- **Motion:** one orchestrated moment, the hero cells settling into populations. `prefers-reduced-motion` skips it.
- **Deliberate absences:** no gradient hero, no glass cards, no icon-in-a-circle feature grid, no stock imagery.
- **Accessibility:** skip link, visible focus rings, `aria-pressed`/`aria-selected` state, arrow-key tabs, text alternatives on charts.

## F. Database model

**Built:** in-memory TypeScript types in `src/data/schema.ts` (User, Project, Dataset, Sample, Experiment, Workflow,
AnalysisRun, Result, Figure, EvidenceSource, ScientificClaim, Publication, Method, and reference entities).
**Specified:** the persistent form below. It is a design sketch: the DDL has not been run against a database.

```sql
create table users        (id uuid primary key, name text not null, orcid text, role text not null check (role in ('owner','collaborator','viewer')));
create table projects     (id uuid primary key, slug text unique not null, title text not null, status text not null default 'placeholder');
create table datasets     (id uuid primary key, project_id uuid references projects, title text not null,
                           provenance text not null check (provenance in ('simulated','real')),
                           accession text, fingerprint text not null, storage_uri text, created_at timestamptz default now());
create table samples      (id uuid primary key, dataset_id uuid references datasets, donor_id text not null, condition text not null, batch text);
create table analysis_runs(id uuid primary key, project_id uuid references projects, dataset_id uuid references datasets,
                           params jsonb not null, engine text not null, environment_digest text, code_uri text,
                           status text not null, started_at timestamptz, finished_at timestamptz, result_hash text);
create table results      (id uuid primary key, run_id uuid references analysis_runs, kind text not null, uri text not null, result_hash text not null);
create table evidence_sources(id uuid primary key, kind text not null, doi text, pmid text, verified boolean not null default false, verified_by uuid references users, verified_at timestamptz);
create table claims       (id uuid primary key, project_id uuid references projects, statement text not null, simulated boolean not null default false);
create table claim_layers (claim_id uuid references claims, level text not null check (level in ('observed','statistical','literature','inference','hypothesis')),
                           text text not null, run_id uuid references analysis_runs, source_id uuid references evidence_sources,
                           test text, adj_p double precision, primary key (claim_id, level),
                           check (level <> 'literature' or source_id is not null),
                           check (level <> 'statistical' or (test is not null and adj_p is not null and run_id is not null)));
create table publications (id uuid primary key, doi text unique, title text not null, venue text, year int, status text not null default 'placeholder');
```

The two `check` constraints on `claim_layers` mirror `validateClaim()` so the rule holds even if application code is bypassed.

## G. API architecture

**Built (external, read-only):** genome annotation comes from the public Ensembl REST API at runtime (`lib/genome/ensembl.ts`): gene lookup with transcripts and exons, chromosome bands, region overlap for neighbours, assembly chromosome lengths, and a batch symbol lookup (POST, falling back to individual GETs). Responses are validated, cached in the browser for 30 days, de-duplicated in flight, and shown with source and retrieval time. On failure the UI states that annotation is unavailable; no coordinates are stored or invented.


**Built:** none. Views read through `data/provider.ts`, whose default provider generates the simulated dataset in the browser.
**Specified** REST surface (JSON, token auth, all writes audit-logged):

```
GET   /datasets                     list, with provenance flag
GET   /datasets/{id}/tables/{name}  chunked Arrow/Parquet or JSON tables (replaces the simulator provider)
POST  /analysis-plans               body: question -> plan (Planner, section H)
POST  /analysis-plans/{id}/approve  human approval; required before run
POST  /analysis-runs                body: plan_id, params -> 202 {run_id}
GET   /analysis-runs/{id}           status, provenance, result_hash
GET   /analysis-runs/{id}/logs      streamed
GET   /analysis-runs/{id}/artifacts code, workflow, environment, results
POST  /claims                       validated server-side with the same rules as validateClaim()
GET   /publications, /methods       content endpoints
```

## H. AI architecture

**Built:** a rule-based planner (`lib/agent/planner.ts`) and a state machine (`lib/agent/machine.ts`). There is **no language model**.
The planner matches the question against seven reviewed templates (differential expression and pathways, composition, spatial
immune architecture, repertoire, multiome regulation, biomarker prediction, splicing) and asks for clarification when none fit.
Execution is locked until the plan is approved; any edit revokes approval.

**Specified** for Phase 3: an LLM proposes plans, but only inside the same constraints.

```
question -> Planner (LLM, retrieves reviewed templates + dataset metadata)
         -> Analytical QC reviewer (independent model + rules; may block)
         -> human approval (required)
         -> Executor (workflow engine, not the LLM)
         -> Result binder (LLM may draft text only from stored results and verified sources)
```

Hard rules: the model never emits numbers that are not read from a stored result; literature claims need a verified
`evidence_source`; every model call is logged with prompt, retrieved context and output hash.

## I. Scientific data model

**Built:** `data/dataset.ts` defines `OmicsDataset`: donors (8: 4 control, 4 disease), per-cell landscape (embedding, type, donor,
panel-gene expression), per-donor pseudobulk counts (400 synthetic genes with planted effects and gene sets), spatial section
(coordinates, region, CD8 clone), repertoire clone-size tables, RNA and ATAC embeddings. Marker genes and ligand-receptor
pairs use real symbols with textbook specificity; regulons are hand-specified for illustration.
Per-gene analysis (`lib/analysis/geneStats.ts`): donor-level mean per cell type, Welch t-test across donors with Benjamini-Hochberg across cell types expressing the gene (mean ≥ 0.1), and tau specificity. Each gene page compares its result with the simulator's programmed effect and labels recovered effects, misses and false positives.
**Specified:** AnnData/MuData/SpatialData objects in object storage, with the DB row holding the fingerprint and URI.

## J. Visualization architecture

Canvas for point clouds (thousands of cells), SVG for everything else. No charting library. Each chart is a small pure
component. Statistical marks follow convention (volcano: nominal P on y, adjusted P for colour). Scales are stated on the
figure. Log axes are labelled. Interactivity is hover (or tap on touch screens), click-to-isolate and click-for-detail, never required to read the figure. Every Explorer and gene-page figure exports: SVG with computed styles inlined and theme variables removed, or PNG at 2x composed with its legend and a provenance footer. The genome track and karyogram are drawn in pixel space from the measured width, with lane packing so labels never overlap.
**Specified:** WebGL point renderer for >500k cells, and server-side tiling for spatial data.

## O. Risks and limitations

- **Everything shown is simulated.** Effects are planted by the simulator, so recovered effects show that the code works, not that any biology is true. Gene IDs in the DE table are synthetic.
- **Demo statistics are simple.** Welch t-tests on logit proportions and log2 CPM stand in for scCODA/Milo and edgeR/DESeq2/limma-voom. This is stated in each method record.
- **Generated code is not executed.** R, Python and Snakemake files are templates and are labelled "not executed". Reproducibility is therefore reported as incomplete until an executed, containerised run exists.
- **Method references are unverified.** They are listed from general knowledge without DOIs and flagged in the UI. A person must check each one.
- **The Agent is not intelligent.** It is a router over reviewed templates. Its value is the enforced review gate, not analytical judgment.
- **Content is empty by design.** Publications, biography and project results need the author. Publishing placeholders as if real would break the platform's central promise.
- **Browser-only compute** limits dataset size; real data need the Phase 2/3 backend.
- **Genome pages depend on Ensembl and were tested only against stand-in responses.** The build sandbox had no network, so rendering, parsing and failure states were checked with fabricated fixtures intercepted in the browser. The first run against the live API is the real test; the batch POST lookup in particular depends on Ensembl allowing cross-origin POST (it falls back to GETs if not).
- **Hosted pages may block Ensembl.** A page served under a content-security policy that does not allow rest.ensembl.org (for example a claude.ai published artifact) shows the unavailable state. Open the downloaded file, or host it without that restriction.
- **Many tests per gene.** Each gene page corrects across cell types, not across all 48 genes; the gene-page method record says so.
- **Fonts** need network access at first load; offline they fall back to system fonts.
- **Type checking** of the UI was validated against a stub of the React types in the build sandbox; run `npm run typecheck` after `npm install` to confirm against the real types.
